## What changed and why

### 1. Setup actually lets every player place (engine + UI)
- `createInitialGameState` now separates **board layout** (`setupMode: 'first' | 'standard'`) from **starting placement** (`placement: 'fixed' | 'draft'`). Fixed positions only exist on the First Game board; the Standard board is always drafted. Defaults keep old behaviour for the engine (`first` → `fixed`), so all engine tests and the 500-game fuzz suite are unchanged.
- The **UI defaults to `placement: 'draft'` with a roll-off**: everyone rolls, highest goes first, towns are placed clockwise, cities back anticlockwise (last player places twice in a row). The city grants the starting hand.
- Reducer: `lastDiceRoll` is cleared when the draft ends so the roll-off is not shown as a production roll on turn 1.
- **Setup coach** (`SetupCoach.tsx`) replaces the build palette in the dock while drafting: who places what, the snake order (piece glyphs in player colours), and a live preview of a hovered corner (hexes, numbers, production dots, harbor, and for cities the exact starting hand). The board shows a translucent ghost piece on hover. Bot placements are paced (≈1 s) so people can follow them.
- Earlier the coach floated over the board and blocked clicks on top intersections — keep board overlays `pointer-events: none` unless they must be interactive.

### 2. Pieces and hazard tokens (`src/ui/WoodenPiecesSvg.tsx`)
Modelled on `UI-design-style.png` / `player-mat-reference.png`:
- **Town**: low hexagon with one full concave edge facing its plant.
- **City**: taller hexagon whose three alternating edges are concave notches facing the three adjacent hexes; roads meet the flat edges.
- Notches are arcs centred on the plant socket (`PLANT_SOCKET_DIST = 15.5`, `PLANT_RADIUS = 7`), so plant discs nest exactly; geometry is generated by `notchedHexPath`.
- Extrusion is drawn in screen space (the old pieces rotated their own shadow), with wood-grain gradients from `PieceDefs` (render `<PieceDefs />` in any SVG that draws pieces; every fill has a colour fallback).
- **Hazard**: the grey felt cardboard cog with a real centre hole (even-odd path). On a hex it lies over the number disc — the number stays readable, the hex art and disc are greyed out. On a building the player's piece shows through the hole.
- Newly placed pieces/hazards drop in (`usePlacementTimes` in `IslandBoardSvg.tsx` remembers first-seen times so hovers do not replay the animation).

### 3. Board
- The island group (lattice, hexes, roads, pieces, harbors, coastal shelf) is drawn in `HEX_RADIUS` units and scaled by `ISLAND_SCALE = 1.17` around the centre (`ISLAND_TRANSFORM` in `theme.ts`), so it fills the frame like the printed board. Ring furniture (VP/GF tracks, event islands) is unscaled; the GF widget and whale pod were moved clear of harbors (verified by the e2e collision check).
- Placement targets are larger pulsing markers; inspector/clean-hazard hex targets only fill on hover.

### 4. Layout & design system
`src/ui/tabletop.css` holds all tokens and component styles (imported from `main.tsx`; unit tests don't load CSS).
- Two surfaces: **card stock** (`--card`, with a visible cardboard edge shadow) for table components, **harbour ink** (`--ink-*`) for system chrome; **volt** (`--volt`) marks the single primary action. Fonts: Bricolage Grotesque (display/numbers) + Atkinson Hyperlegible (UI) from Google Fonts with system fallbacks.
- Shell (`TabletopApp.tsx`) composes: `TopBar` · `PlayersRail` (player boards + activity feed) · board area (pan/zoom, toasts, roll-off, zoom control) · `TableRail` (event bag, dice tray, supply, awards) · `ActionDock` (hand, build palette, energy popover, primary action, player-board drawer).
- Build palette availability comes from `legalActions` via `gameView.ts#getBuildOptions`, including the reason a button is disabled ("Needs 1 brick", "One power plant per turn", "No legal spot").
- Responsive: ≥1600×940 scales the chrome up; ≤1100 two-column dock; ≤900 one scrolling column (board → hand/build/action → rails).

### 5. Dialogs & copy
- `Modals.tsx` colours were remapped onto the ink tokens. New lobby ("New game" sheet: seats, Island, Starting pieces, More options), discard/event-choice dialogs with tappable resource cards, celebratory victory screen, plain-language board prompts.
- `gameView.ts#humanizeLog` rewrites engine log lines for the feed and toasts (event names instead of ids, no node/edge/hex numbers). Engine log strings were left untouched (tests assert on some of them).

### 6. Persistence
Every action saves `{ state, config }` to `localStorage['catan_new_energies_saved_game_v2']`; a plain URL resumes an unfinished game ("Welcome back" toast). Any game URL param (`seed`, `setup`, `placement`, `players`, `bots`, `mode`, `room`, `scenario`) starts fresh.

### 8. Follow-up: discard bug, rule audit, player board redraw
- **Discarding on a 7 did nothing.** `applyAction` only accepts actions that exactly match `legalActions`; for discards that list stopped at 50 combinations and was compared with raw `JSON.stringify`, so the dialog's answer (click order, zero entries) was rejected and the error swallowed. Fixed with `canResolveDiscard` (validates against the rules directly: exactly half rounded down, whole numbers, never more than held, right player) and a key-order-insensitive `isActionEqual` (`canonicalJson`). Rejected moves now show a red "That move is not allowed" toast with the reason.
- **Rule audit** against `rules_text.txt`: production and hazard clearing (incl. the inspector exception and the hex+city example), roll of 7, inspector moves and steals, roads (not past opponent buildings), towns (distance rule), cities, power plant cutouts and the one-per-turn limit, energy uses and the 5-energy cap, supply/harbor/player trades, warehouse, development cards and both win conditions all match. Hardened: trade offers must be whole non-negative numbers of real cards; Research Grant must name resource/science cards. The empty-bag tie-breaks after "most points" (most renewables, lowest LF) are engine additions the rules do not specify.
- Tests: `src/engine/__tests__/decision-validation.test.ts` (discards, key order, malformed trades, Research Grant, a full real roll of 7 → discards → inspector → steal), a UI discard test, and an e2e discard test.
- **Player board** (`PlayerMat.tsx`) redrawn: full rounded cardboard rectangle (no stepped corners), piece-shaped slots using the exported `TOWN_PATH_D`/`CITY_PATH_D` with upright pieces, a bridge window bordered on all four corners, puffy smoke/clouds instead of pale wedges, new factory and hills, card-stock cost tabs and energy tiles. The visual e2e checks all 24 slots sit inside the printed area.

### 9. Follow-up: resource art, hazard token, footprint widget, and a wrong rule
- **Resource icons** (`ResourceIconSvg`, `WoodenPiecesSvg.tsx`) follow the rulebook cards: stacked logs with growth rings, clay bricks with cores, a cone of white thread plus a small spool, bread with slices, and I-beams. They are used everywhere resources appear, so change them in one place.
- **Hex clean-up:** the little green harvester on fields and the black mine portal on mountains were removed.
- **Natural hazard token** is now `HazardTokenSvg` (was a cog): wobbly oil-spill outline (`SPILL_WAVES`), white die-cut border, dark thickness, speckled face, and a hole sized to the number disc on hexes or the piece on buildings. Blocked hexes are no longer greyed out; the token alone marks them.
- **Footprint widget:** the bag icon, label gap and pill are laid out explicitly and checked by `e2e/gf-widget.spec.ts` for 1, 2 and 3 draws per turn (`?scenario=draws2|draws3`).
- **Wrong rule removed:** `applyBuildPowerPlant` used to place a hazard token when a fossil plant was built. The rulebook (p. 15) says only that the footprint rises. Hazards come only from events (Air Pollution, Environmental Pollution, Rain & Flooding). The 500-game fuzz suite now fails if any other action increases the hazards on the board.

### 10. Follow-up: piece fit, plant layering
- **Pieces are centred on their intersection** (`WoodenPiece` raises the top face by half the wall thickness), so a city reaches equally far toward a road above or below. `CITY_REACH` (13.5) is sized to end exactly where a road starts (`ROAD_LENGTH` 29); `piece-fit.test.ts` keeps them in step, so change both together. `?scenario=cityfit` shows roads on every side of every building.
- **Plants sit in the notches, not on top of them.** The city (wall 5) is taller than a plant disc (thickness 0.3 x radius); `plantRestOffset` puts the disc on the board level with the building's base. Layering is per notch (`plantSlot` in `IslandBoardSvg.tsx`): plants up the screen are drawn behind their building, plants down the screen in front of it, so all six directions work. Placement targets live in their own top layer (`plant-targets-layer`). `?scenario=plantfit` fills every notch.
- Steel and brick icons both show two pieces side by side with the third laid across the middle.

### 11. Follow-up: victory point track, cursor, hidden-information log
- **Victory point track** (`SeaFrameSvg.tsx`, `VP_ARC`, `VP_TITLE`): a band concentric with the rim, counters 3..10 (everyone starts with a town and a city, so 3 is the lowest score), label on the sea below. Geometry is generated by `vpBandPath`, so change the constants rather than the path. `e2e/vp-track.spec.ts` checks the fit with `isPointInFill`.
- **Cursor:** only `grab` / `grabbing` are non-native cursors in the game, and on Windows browsers draw a low-resolution bitmap for them, which looks pixelated on 4K. They are replaced by `public/cursors/{grab,grabbing}-{1..4}x.png` via `image-set()` (native cursor as fallback). Regenerate with `npm run cursors:build` after editing the drawings in `scripts/make-cursors.mjs`. Cursors cannot be screenshotted, so the e2e test checks the computed style and the files; judge the look on a real 4K screen.
- **Hidden information must never reach the log.** The green event discs under renewable plants are dealt face down; the log used to name the disc added to the bag. Anything in `state.log` is shown to everyone and sent over the network, so only write what the whole table could see.

## Gotchas for the next agent
- **Line endings**: the repo is LF. Python's text mode on Windows writes CRLF — use `open(..., newline='')`.
- **Prettier is not applied to legacy files** (`SeaFrameSvg.tsx`, `PlayerMat.tsx`, `Modals.tsx`, engine). Running `prettier --write` on them produces huge noise diffs; format only new files if at all.
- **Node 26 + Vitest**: Node defines a flag-gated global `localStorage` that shadows happy-dom's (it is `undefined`). Tests that need storage stub it with `vi.stubGlobal` (see the resume test).
- The e2e visual spec rewrites `docs/ui-after-*.png` on every run — commit them when the UI changes intentionally.
- Bots act from a `useEffect` timer keyed on `gameState`; anything that should pause them must be added to that effect's guard.
