## What changed and why

### 1. Setup actually lets every player place (engine + UI)
- `createInitialGameState` now separates **board layout** (`setupMode: 'first' | 'standard'`) from **starting placement** (`placement: 'fixed' | 'draft'`). Fixed positions only exist on the First Game board; the Standard board is always drafted. Defaults keep old behaviour for the engine (`first` → `fixed`), so all engine tests and the 500-game fuzz suite are unchanged.
- The **UI defaults to `placement: 'draft'` with a roll-off**: everyone rolls, highest goes first, towns are placed clockwise, cities back anticlockwise (last player places twice in a row). The city grants the starting hand.
- Reducer: `lastDiceRoll` is cleared when the draft ends so the roll-off is not shown as a production roll on turn 1.
- **Setup coach** (`SetupCoach.tsx`) replaces the build palette in the dock while drafting: who places what, the snake order (piece glyphs in player colours), and a live preview of a hovered corner (hexes, numbers, production dots, harbor, and for cities the exact starting hand). The board shows a translucent ghost piece on hover. Bot placements are paced (≈1 s) so people can follow them.
- Earlier the coach floated over the board and blocked clicks on top intersections — keep board overlays `pointer-events: none` unless they must be interactive.

### 2. Pieces and hazard tokens (`src/ui/WoodenPiecesSvg.tsx`)
Modelled on `UI-design-style.png` / `player-mat-reference.png`:
- **Town**: low hexagon with one full concave edge facing its plant.
- **City**: taller hexagon whose three alternating edges are concave notches facing the three adjacent hexes; roads meet the flat edges.
- Notches are arcs centred on the plant socket (`PLANT_SOCKET_DIST = 15.5`, `PLANT_RADIUS = 7`), so plant discs nest exactly; geometry is generated by `notchedHexPath`.
- Extrusion is drawn in screen space (the old pieces rotated their own shadow), with wood-grain gradients from `PieceDefs` (render `<PieceDefs />` in any SVG that draws pieces; every fill has a colour fallback).
- **Hazard**: the grey felt cardboard cog with a real centre hole (even-odd path). On a hex it lies over the number disc — the number stays readable, the hex art and disc are greyed out. On a building the player's piece shows through the hole.
- Newly placed pieces/hazards drop in (`usePlacementTimes` in `IslandBoardSvg.tsx` remembers first-seen times so hovers do not replay the animation).

### 3. Board
- The island group (lattice, hexes, roads, pieces, harbors, coastal shelf) is drawn in `HEX_RADIUS` units and scaled by `ISLAND_SCALE = 1.17` around the centre (`ISLAND_TRANSFORM` in `theme.ts`), so it fills the frame like the printed board. Ring furniture (VP/GF tracks, event islands) is unscaled; the GF widget and whale pod were moved clear of harbors (verified by the e2e collision check).
- Placement targets are larger pulsing markers; inspector/clean-hazard hex targets only fill on hover.

### 4. Layout & design system
`src/ui/tabletop.css` holds all tokens and component styles (imported from `main.tsx`; unit tests don't load CSS).
- Two surfaces: **card stock** (`--card`, with a visible cardboard edge shadow) for table components, **harbour ink** (`--ink-*`) for system chrome; **volt** (`--volt`) marks the single primary action. Fonts: Bricolage Grotesque (display/numbers) + Atkinson Hyperlegible (UI) from Google Fonts with system fallbacks.
- Shell (`TabletopApp.tsx`) composes: `TopBar` · `PlayersRail` (player boards + activity feed) · board area (pan/zoom, toasts, roll-off, zoom control) · `TableRail` (event bag, dice tray, supply, awards) · `ActionDock` (hand, build palette, energy popover, primary action, player-board drawer).
- Build palette availability comes from `legalActions` via `gameView.ts#getBuildOptions`, including the reason a button is disabled ("Needs 1 brick", "One power plant per turn", "No legal spot").
- Responsive: ≥1600×940 scales the chrome up; ≤1100 two-column dock; ≤900 one scrolling column (board → hand/build/action → rails).

### 5. Dialogs & copy
- `Modals.tsx` colours were remapped onto the ink tokens. New lobby ("New game" sheet: seats, Island, Starting pieces, More options), discard/event-choice dialogs with tappable resource cards, celebratory victory screen, plain-language board prompts.
- `gameView.ts#humanizeLog` rewrites engine log lines for the feed and toasts (event names instead of ids, no node/edge/hex numbers). Engine log strings were left untouched (tests assert on some of them).

### 6. Persistence
Every action saves `{ state, config }` to `localStorage['catan_new_energies_saved_game_v2']`; a plain URL resumes an unfinished game ("Welcome back" toast). Any game URL param (`seed`, `setup`, `placement`, `players`, `bots`, `mode`, `room`, `scenario`) starts fresh.

```bash

```

Dev-only visual scenarios: `?scenario=showcase` (mid-game with plants, hazards, moved inspector), `discard`, `cardchoice`, `victory`.

## Gotchas for the next agent
- **Line endings**: the repo is LF. Python's text mode on Windows writes CRLF — use `open(..., newline='')`.
- **Prettier is not applied to legacy files** (`SeaFrameSvg.tsx`, `PlayerMat.tsx`, `Modals.tsx`, engine). Running `prettier --write` on them produces huge noise diffs; format only new files if at all.
- **Node 26 + Vitest**: Node defines a flag-gated global `localStorage` that shadows happy-dom's (it is `undefined`). Tests that need storage stub it with `vi.stubGlobal` (see the resume test).
- The e2e visual spec rewrites `docs/ui-after-*.png` on every run — commit them when the UI changes intentionally.
- Bots act from a `useEffect` timer keyed on `gameState`; anything that should pause them must be added to that effect's guard.
